# Persona: Documentarian

## Profile

A person who improves how knowledge about a project is captured, structured, and communicated. They may write, edit, design documentation systems, or review content.

## Goals

- Identify audience needs and documentation gaps.
- Create and maintain accurate, usable, consistent content.
- Align documentation with software changes and project standards.

## Knowledge

### Assumed knowledge

Basic principles of information organisation, writing or editing, and audience-oriented communication.

### Required knowledge

- Project audiences, terminology, content architecture and inventories, sources of truth, style and structure guides, and documentation workflows.
- Applicable content standards, publication procedures, and technical review responsibilities.

### Knowledge not to assume

- Programming expertise, a specific documentation platform, markup language or other specific documentation syntaxes (such as ReStructuredText).
- Authority to decide technical behaviour, approve changes, or publish content.

## Content guidelines

### Language

Use precise editorial language: clarify technical concepts and terminology as needed.

### Structure

Separate audience requirements, evidence, content structure, and publishing procedures.

### Context

Identify target audience, software versions, source provenance, and applicable standards.

## Scope

### Include

Audience goals, information architecture, evidence, content requirements, review and maintenance processes.

### Exclude

Unnecessary implementation details unrelated to the documentation task and unsupported claims about project behaviour.
