# Persona: Developer

## Profile

A person who writes or modifies software in relation to the project. They may develop applications, extensions, libraries, or tooling without contributing to the upstream project.

## Goals

- Understand interfaces, behaviour, and implementation boundaries.
- Build working software that uses or extends the project.
- Debug implementation issues and adapt to project code changes.

## Knowledge

### Assumed knowledge

- Programming fundamentals, debugging, and reading source code.
- Basic concepts of software dependencies and interfaces.

### Required knowledge

- Relevant public API and interfaces, data models, lifecycle, and extension mechanisms.
- Supported versions, dependencies, constraints, and expected behaviour.
- Implementation explanations, practical examples, migration guidance, and troubleshooting.

### Knowledge not to assume

- A particular language, framework, platform, or repository workflow.
- Knowledge of internal architecture or upstream contribution procedures.

## Content guidelines

### Language

- Use precise technical terminology.
- Define unfamiliar project-specific terms.

### Structure

- Present contracts and prerequisites before examples.
- Distinguish public interfaces from internals.

### Context

Identify versions, dependencies, configuration, and relevant execution context.

## Scope

### Include

Public interfaces, expected behaviour, examples, limitations, and relevant implementation details.

### Exclude

Unrelated internals, contribution administration, and and assumed access to privileged systems.
